# 스마트 청킹 (qmd)

[[qmd]]가 임베딩 전에 문서를 나누는 방식(README 서술). 하드 토큰 경계 대신 **자연스러운 마크다운 끊김 지점**을 점수로 골라 의미 단위(섹션, 문단, 코드 블록)를 유지한다.

- 목표 크기 약 900토큰, 15% 겹침. 청크는 `title | text` 형식으로 임베딩되고 문서 해시, 순번(seq), 문자 위치(pos)와 함께 저장.
- 끊김 점수: H1 100, H2 90, H3 80, H4 70, H5 60, H6 50, 코드 펜스 80, 수평선 60, 빈 줄 20, 목록 항목 5, 줄바꿈 1.
- 알고리즘: 목표 직전 200토큰 창에서 후보를 찾고 `최종점수 = 기본점수 x (1 - (거리/창)^2 x 0.7)`로 가장 높은 곳에서 자른다. 200토큰 앞의 제목(약 30점)이 목표 지점의 단순 줄바꿈(1점)보다 이긴다.
- 코드 펜스 내부의 끊김은 무시한다.
- **AST 청킹**(`--chunk-strategy auto`): 코드 파일(`.ts .tsx .js .jsx .py .go .rs`)은 tree-sitter로 클래스·함수·import 경계를 추가 후보로 쓴다. 마크다운은 항상 정규식 방식. tree-sitter 문법이 없으면 자동으로 정규식으로 대체.

이 위키는 마크다운만 있으므로 AST 청킹은 해당 없고, 제목(`##`)을 잘 쓰면 청크 품질에 유리하다는 정도가 시사점이다(추론).
