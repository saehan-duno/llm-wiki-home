# 하이브리드 검색

[[qmd]]가 쓰는 검색 파이프라인(README 기준).

## 흐름

1. **쿼리 확장**: 미세조정된 LLM이 질의를 `lex`(BM25용 키워드), `vec`(밀집 문장), `hyde`(가상 문서) 유형으로 확장. `lex`는 BM25/FTS로, `vec`와 `hyde`는 벡터 검색으로만 보낸다. 원 질의는 양쪽에 모두 보낸다.
2. **병렬 검색**: 각 질의를 FTS5(BM25)와 벡터 인덱스에서 검색.
3. **RRF 융합**: `score = sum(1/(k+rank+1))`, k=60. 원 질의는 가중치 x2. 어느 목록에서든 1위는 +0.05, 2~3위는 +0.02 보너스.
4. **후보 선택**: 상위 후보(README 본문은 30개, 옵션 기본값은 40개)만 재랭킹.
5. **LLM 재랭킹**: qwen3-reranker가 문서별 관련도 산출.
6. **위치 인식 블렌딩**: RRF 순위 1~3위는 검색 75% / 재랭커 25%, 4~10위는 60/40, 11위 이하는 40/60.

## 왜 이렇게 하나 (README의 설명)

순수 RRF는 확장 질의가 맞지 않을 때 정확 일치를 희석한다. 1위 보너스는 원 질의 1위 문서를 보존하고, 위치 인식 블렌딩은 재랭커가 확신 있는 검색 결과를 망치지 못하게 한다.

## 점수

| 백엔드 | 원점수 | 변환 |
|---|---|---|
| FTS (BM25) | SQLite FTS5 BM25 | 절댓값 (0~약 25+) |
| 벡터 | 코사인 거리 | `1/(1+거리)` (0~1) |
| 재랭커 | LLM 평가 | 0~1 |

해석: 0.8~1.0 매우 관련, 0.5~0.8 보통, 0.2~0.5 약간, 0.0~0.2 낮음.

## 명령

`qmd search`(BM25만), `qmd vsearch`(벡터만), `qmd query`(전체 파이프라인, 최고 품질). `--no-rerank`로 재랭킹을 건너뛰어 CPU에서 속도를 높이고, `--explain`으로 점수 분해를 본다.

## 성능 주장

README의 벤치마크 예시 픽스처 결과로 bm25 약 0.50, vector 약 0.70, hybrid/full 약 1.00. 저자가 보고한 수치이며 독립 검증은 아니다.

## 주의: README 내부 불일치

쿼리 확장 개수(변형 2개 vs 1개), 재랭크 후보 수(30 vs 40), 재랭커 점수 방식(0~10 평점 vs yes/no logprob)이 절마다 다르게 적혀 있다. 자세한 표는 [[qmd-readme]] 참고. 위 흐름은 서로 일치하는 부분만 적었다.

[[rag]]의 검색 단계를 로컬에서 구현하는 방식이며, [[llm-wiki]]가 커져 `index.md`만으로 부족할 때의 선택지다. 관련: [[smart-chunking]], [[metadata-filtering]]
